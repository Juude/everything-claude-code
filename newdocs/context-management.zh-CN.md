# Context（上下文）管理机制与最佳实践

在当前项目中，Context（上下文）管理是确保高效率、低消耗及保持长效开发过程的核心议题。项目通过不同层次和手段组合来精细化地控制和优化 Token 消耗和对话记忆。下面将对 `contexts/` 文件夹的作用、项目内的上下文管理策略及其最佳实践进行详细介绍。

## 1. `contexts/` 文件夹的作用

`contexts/` 文件夹中的文件主要用于**动态系统提示注入（Dynamic System Prompt Injection）**。

在通常的用法中，所有的指南和规则可能被统统放进全局 `CLAUDE.md` 或是项目级的 `.claude/rules/` 中，每次会话全部加载，造成极大的 Token 浪费。`contexts/` 文件夹通过区分不同的工作模式，让你能够做到按需加载特定的上下文。这让系统提示的权重最高，并且只包含当前任务绝对必要的信息。

### 具体的模式配置

文件夹中默认包含了三个核心模式文件：

- **`contexts/dev.md` (开发模式)**
  - **核心聚焦**：功能实现、代码编写、构建和测试。
  - **指导行为**：偏好能运行的方案而非过度完美的设计；写代码优先于解释；鼓励原子化提交和边写边测。
  - **工具倾向**：倾向于使用 `Edit`, `Write` 修改代码，以及 `Bash` 运行测试/构建。

- **`contexts/review.md` (代码审查模式)**
  - **核心聚焦**：PR 审查、代码质量、安全性、可维护性分析。
  - **指导行为**：先彻底阅读，再评论；不仅要指出问题，更要提供修复建议；按严重程度排列问题优先级。
  - **涵盖清单**：逻辑错误、边界场景、错误处理、安全漏洞（注入、授权、密钥等）、性能和覆盖率等。

- **`contexts/research.md` (研究与探索模式)**
  - **核心聚焦**：在采取行动前充分理解代码库与背景。
  - **指导行为**：在得出结论前广泛阅读；主动提问澄清；在完全理解前不要急于写代码；边探索边记录发现。
  - **工具倾向**：大量使用 `Read`, `Grep`, `Glob` 来梳理代码脉络，并利用 `WebSearch` 获取外部文档。

### 使用方法

通过命令行参数在启动 Claude 时注入：

```bash
# 别名示例
alias claude-dev='claude --system-prompt "$(cat ~/.claude/contexts/dev.md)"'
alias claude-review='claude --system-prompt "$(cat ~/.claude/contexts/review.md)"'
alias claude-research='claude --system-prompt "$(cat ~/.claude/contexts/research.md)"'
```

## 2. 项目中的 Context 管理机制

除了 `contexts/` 文件夹，该项目还提供了一系列机制来对抗上下文腐化（Context Rot）并优化 Token 成本：

### 2.1 MCP (Model Context Protocol) 限制与 Token 优化

MCP 提供了与外部服务（如 GitHub、数据库等）交互的强大工具链，但每个 MCP 的工具描述都会极大地占用你的上下文窗口（例如一个包含众多工具的 MCP 会把原本 200k 的上下文压缩到只剩 70k）。

- **策略**：保持配置的 MCP 丰富，但**禁用绝大部分不用的 MCP**。
- **经验法则**：项目级启用的 MCP 不要超过 10 个，激活的工具总数保持在 80 个以内。对大量重复的 CLI 命令（如 `gh pr create`），推荐使用技能（Skills）/命令（Commands）替代 MCP 以释放上下文。

### 2.2 内存持久化（Memory Persistence）与 Hooks

长时间对话会使上下文变得庞杂。项目提供了一套跨会话保存上下文状态的机制（位于 `hooks/memory-persistence/` 等处），以实现每天/每次任务的新鲜开局：

- **PreCompact Hook（压缩前保存）**：在上下文即将被压缩时，将当前重要状态保存到本地文件中。
- **Stop Hook (会话结束)**：会话结束时，总结当前进度、成功的尝试和失败的经验，保存到 `.claude` 文件夹中的会话存储文件。
- **SessionStart Hook (会话开始)**：新会话开始时自动加载上一次中断的文件，无缝衔接。

### 2.3 战略性压缩（Strategic Compacting）

项目支持手动触发上下文压缩。当探索与规划阶段（Plan mode）结束，所有必要的背景知识已经沉淀到了代码或总结文件（如 `plan.md`）中，此时应该清理掉之前的探索对话记录，专注于执行。通过 `/compact` 命令清除无用历史，仅保留系统核心状态和最近的任务说明。

### 2.4 子代理（Subagents）上下文隔离

子代理（如 `planner.md`、`code-reviewer.md`）是主智能体分配具体任务的对象。
- **问题**：主代理拥有高层次的目标上下文，如果把全部东西丢给子代理，既昂贵又无效。
- **解决机制**：通过“迭代检索模式（Iterative Retrieval Pattern）”。每次将极其专注的任务和客观文件交给特定的子代理。子代理通过受限的工具权限执行任务，并只返回精简的摘要和结果，而不产生庞大的交互日志，从而大大降低了主会话的 Token 负担。

## 3. Context 管理的最佳实践总结

1. **情境化启动**：不要一直使用全局默认的 Agent 进行所有工作。根据任务类型（开发、研究、审查），使用 `contexts/` 中的专用系统提示（如 `--system-prompt`）启动 Claude。
2. **警惕 MCP 滥用**：定期使用 `/mcp` 检查当前开启的协议。将不常用的关闭，把常用的外部调用转换为简单的 Shell 技能。
3. **分而治之与工作流隔离**：利用 `Subagents` 处理独立模块的工作，并通过输出文件（如 `research-summary.md` → `plan.md` → 实际代码）传递进度，而不是在单个会话中处理所有步骤。
4. **养成持久化的习惯**：对于需要隔天或长期继续的工作，在结束前要求生成一份状态文件（包含已完成、待完成以及关键的发现），第二天将此文件作为上下文提供，避免重蹈覆辙。
5. **及时压缩历史**：一旦确认方案，并且不打算再参考此前的“踩坑”过程，立即执行战略压缩，让执行阶段保持“轻装上阵”。
